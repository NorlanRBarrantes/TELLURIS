# EXP-007 — Five-pillar expansion of TELLURIS

**Project Uriel — NASA Space Apps Challenge 2026**  
**Date:** 2026-11-15, Costa Rica  
**Status:** Accepted product requirements. None of the roadmap items is presumed deployed or independently scientifically validated by this planning document.

## Objective

Make TELLURIS a global, bilingual, evidence-driven Earth-system investigator: discover a question, choose appropriate NASA data, identify the spatial/temporal support, visualize observations, estimate changes, test statistical assumptions, and export reproducible evidence. Preserve previous EXP-001–006 scientific safeguards. Each of the five improvements below must have authentic provenance, deterministic computational results, explicit uncertainty and source attribution.

## A. Independent NASA precipitation comparison — very high priority

**In place:** EXP-006 NASA POWER vs GPM IMERG Final V07 comparison algorithm, local import parser, native HDF5 extractor and original-data provenance schema.

**Missing:** NASA original IMERG granules; the comparator has not performed an actual source-independent precipitation study. Acquire NASA GPM_3IMERGM_07 Final V07 monthly HDF5 from Earthdata (authorized account), store exact filenames/hashes, use complete monthly records for matched years (first target 2001–2024), validate mm/hr vs POWER mm/day, cell footprints, gauges used by both products, and compare bias/MAE/RMSE/correlation/trend *without asserting causation*. Preserve conflicting or inconclusive findings.

**Acceptance:** Reproducible native NASA originals + hashes, independent numerical QA, named source collection/version/resolution/period, real JSON import and ES/EN browser capture. Do not equate a self-reported manifest to cryptographic NASA authenticity. See [EXP-006](EXP-006-IMERG-CROSS-VALIDATION.md).

## B. Scientific NASA layers on 3D globe — high visual/scientific priority

**In place:** Three.js geographical globe, clickable coordinates and NASA POWER navigation; colors are schematic, not satellite measurements.

**Target:** A source-specific layer registry (prefer official NASA GIBS/Worldview products after endpoint and rights verification), map projection compatibility, dated observation, pixel/footprint resolution, legend, unit, source and source-license link, cached/unavailable states, mobile/WebGL fallback and accessibility. Clicking a point opens the associated verified time-series query. Keep NASA satellite imagery distinct from a modeled trend field; don't infer measured temperature from background RGB.

**Acceptance:** One genuine NASA geospatial product visualized, official product/date legend, correct geolocation and ES/EN interaction tests, clear fallback. **Not yet implemented.**

## C. Monthly/seasonal and historical comparison — high priority

**Target:** Retain trustworthy NASA POWER source months for complete years, show a month-of-year cycle, two predeclared historical windows, explicit baseline and month-matched anomalies, plus quarter/season sensitivity. Account for precipitation rate-to-total conversion and leap days, day-weighted means, missing months and source-specific variable types. Wind bearing is circular and cannot be analyzed as a linear temperature anomaly. Show period and unit in every chart. A 5-year internally selected period is *not* a standard 30-year climatology.

**Acceptance:** Pure-function unit tests against synthetic fixtures; independent real NASA monthly replay; bilingual web comparison; selected period, baseline, n and missingness; no asserted significance without appropriate dependence-aware inference.

**Status:** Initial EXP-007C descriptive source-month panel, month-matched differences/anomalies and calendar-quarter summaries are now implemented in GitHub source with tests. User-defined fixed climatological baselines, independent source replay and production/browser QA remain pending.

## D. Real evidence-grounded AI investigator — high discovery priority

**In place:** Deterministic, rule-based evidence assistant, *not* a large language model.

**Target:** Optional server-side LLM adapter after checking BanaHosting outbound HTTPS/PHP runtime. Keep provider secrets off all public web assets and git. Pass structured immutable NASA-source evidence generated by the numerical core; constrain outputs to citations, observations, inferences and limitations. Allow question-to-variable suggestions, plain-language analysis and research follow-ups. The LLM may neither fabricate a source nor recompute/overwrite the underlying p-values, slopes or coordinates. Add identity/model disclosure, rate limits, timeout, cost budget, schema validation and adversarial prompt-injection tests; retain rules-based fallback.

**Acceptance:** Secret-safe, tested authenticated server adapter, scientific claim validator, refusal under missing evidence, bilingual accessibility and cost/rate controls. **Blocked on runtime/credentials; not connected.**

## E. Printable scientific PDF report — high communication priority

**In place:** EXP-005 downloadable traceable scientific JSON and annual CSV.

**Target:** Source-preserving print report in ES/EN containing observations, SVG chart, parameter/units/coordinates, NASA provenance/version, Sen slope and CI, Mann–Kendall original p with assumptions, time-window sensitivity, missing-data treatment, uncertainty warnings, limitations, bibliography and independent-project attribution. Prefer browser **Print → Save as PDF** initially: it avoids a secret-bearing third-party PDF service and works with static hosting; subsequently consider direct PDF export once browser fidelity, licensing and pagination are tested.

**Acceptance:** Output equality with JSON, safe HTML escaping and no unverified significance labels, print CSS with A4 page breaks, real browser PDF save test and reproducibility link. **Initial source-code print formatter, ES/EN user control and tests added; native direct PDF export and real browser QA remain pending.**

## Order of execution and release gates

1. Protect NASA submission deadline: official project form, public demo, team credits, source/license/AI disclosure and jury-ready 30-second video or 7 slides as authorized by the 2026 guidance.
2. Implement C and E locally with synthetic tests and validate with real NASA input; keep current public product functional.
3. Obtain the actual GPM originals for A; run verified independent comparison before reporting precipitation findings.
4. Deploy B's first source-authentic layer with explicit dates/legend; no unverified raster or inferred color-as-data.
5. Wire D through a verified secure server-side proxy, not from frontend JavaScript.
6. Require green CI, backup, file-hash comparison and human ES/EN + mobile browser verification before public publication. GitHub commits do **not** automatically update BanaHosting. Update VALIDATION and DECISIONS with witnessed evidence.

## Documentation and asset boundaries

The supplied example images are *visual references*, not satellite-data inputs or cleared website licenses; do not copy those third-party images into the product without verifying usage rights. Cite NASA, Natural Earth, Three.js, source collections/DOIs and source code separately. Preserve public-facing documentation in English, with ES/EN product UI. Never invent scientific results to improve a demo.
